# Video export, retention and shrinking

Read this before changing `src/export/`, `src/retention.rs`, `helper/Export.swift` or `helper/Media.swift`.

## Video export (`src/export/`, `helper/Export.swift`)

`apparent export <bundle>` writes one H.264/HEVC + AAC `.mp4`; the `videoExport` flag (default off) only gates the Mac menu's **Export Last Capture as Video…** (→ `~/Movies/Apparent`, progress beside the menu bar icon). Rust decides everything; on Mac the helper renders it from a JSON plan (AVAssetReader → Core Image crop/camera → Core Graphics ink → AVAssetWriter): `crop.rs` (`--crop auto|full|x,y,w,h` — auto is `autocrop` `Scope::Whole` — even-sided output size, audio window), `ink.rs` (strokes via `sketch::freehand_outline`, laser, pins, ripples; sizes mirror `render::annotate_keyframe_in_place`), `camera.rs` (`--zoom`: pure events → camera rects, critically damped springs, never zooms during fast cursor travel; derived from ScreenDemon's click zoom). Everything in the plan is on the video's clock (bundle time − `videoOffsetMs`); Mac `audio.wav` starts `videoOffsetMs` in, an iPhone movie uses its own audio. Output is constant frame rate (screen movies only have frames on change). Test with `cargo test export::`.

On Linux the same Rust crop, ink and camera plans drive an FFmpeg decoder/encoder adapter (`src/export/linux.rs`); install `ffmpeg` and `ffprobe` with H.264/AAC support (HEVC also needs `libx265`). The CLI exports an existing bundle even when the separate GStreamer keyframe decoder is unavailable. The source video stays intact. Export writes a uniquely named partial beside the destination, checks streams and duration, then renames it; failures remove that partial. It refuses to replace source video, saved audio or any existing bundle file; choose a fresh name inside the bundle or an output path outside it. The menu experiment remains Mac-only; the Linux user path is `apparent export <bundle> [--out path] [--zoom]`.

## Retention and shrinking (`src/retention.rs`, `Media.shrink` in `helper/Media.swift`)

For a separate narrated agent walkthrough share copy, see [Agent proof-video tooling](proof-video.md). This repository helper consumes an existing movie and explicit timed explanation; it is not part of ordinary app exports, captures or retention and never modifies source media.

The app's `retention` worker (utility QoS) runs a pass 90 s after launch and hourly (`PASS_EVERY`): heavy media (`handoff::HEAVY_MEDIA`, plus `zoom/` from `DERIVED_MEDIA`) to the Trash after `mediaDays` (default 7, writes `.media-cleaned`), whole bundles after `bundleDays` (30); `"retention"` in `~/.config/apparent/config.json`, Settings › Storage. It skips bundles under a day old or whose folder changed (ctime) in the last day, live `.media-pending`/`.media-sending` markers, `.pinned`, `.deliver.json`, and bundles `retention::claim`ed. Cabled-iPhone `recording.mov` (> 6 Mbps) is re-encoded to HEVC at 1600 px a minute after `finalize_live_capture`, written beside the bundle and renamed over the original; sample times are kept, so `apparent.json` is unchanged. Anything reading `video` must handle it missing (`retention::missing_media_reason`). Try passes on a temp folder with `apparent clean --captures DIR --days-ahead N [--dry-run]`.
