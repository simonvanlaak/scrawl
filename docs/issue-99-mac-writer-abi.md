# Issue 99: candidate-only Mac writer ABI v1

This is an **integrated, Mac-compiled candidate**, not a fully verified recording fix. `helper/RealtimeWriter.swift` is built alone into `libapparent_realtime_writer.dylib`; it is excluded from the `apparent-helper` executable. `build.rs` stages it in `target/{debug,release}/`. The local, remote-staged, preview and release bundles place and sign it at `Contents/Frameworks/libapparent_realtime_writer.dylib`. The remote installer copies the signed staged bundle with `ditto`. The Rust caller `dlopen`s the absolute bundle path derived from its executable's `Contents/MacOS/` directory (or `target/{profile}/libapparent_realtime_writer.dylib` for an uninstalled development binary). Missing library or symbols leave the original recording untouched.

C signatures (`#include <stdint.h>` and `<stddef.h>`):

```c
void *apparent_writer_create_v1(const uint8_t *absolute_utf8_path, intptr_t path_length,
                                int32_t canvas_width, int32_t canvas_height);
int32_t apparent_writer_enqueue_sample_v1(void *handle, const void *borrowed_cmsamplebuffer,
                                           int64_t capture_clock_ms);
int32_t apparent_writer_enqueue_final_rgba_v1(void *handle, const void *rgba,
                                               int32_t width, int32_t height, int64_t pts_ms);
int32_t apparent_writer_finish_v1(void *handle);
void apparent_writer_destroy_v1(void *handle);
int32_t apparent_writer_validate_v1(const uint8_t *absolute_utf8_path, intptr_t path_length,
                                    const void *stop_rgba, int32_t width, int32_t height,
                                    int64_t stop_pts_ms);
```

`create` returns NULL for invalid inputs or writer failure; the candidate path must be absolute, private, non-existing, UTF-8, with byte length 1–4096. Width and height must be positive even values, each ≤16384, with ≤64 million pixels. Caller owns path selection and permissions: this function does **not** inspect or replace `recording.mp4`. A created handle must be destroyed exactly once, never concurrently with any call. Null `destroy` is harmless; other calls with a null handle return 1. Call `finish` once after stopping and draining all SCK callbacks; a second finish returns 5. `destroy` cancels a still-open writer without joining its queue; it is not publication authority. No function is safe to use after destroy. Queued Swift work and AVFoundation completion closures can remain after destroy or a finish timeout. Rust's process singleton retains one dylib reference, including symbol-resolution failures, rather than one reference per capture. It must not unload code those closures can still execute. Loader errors are cached until process restart.

Before native creation, Rust acquires a shared advisory lock on the bundle directory and keeps its descriptor in the writer through finish/validation, including after the caller's 26-second timeout. Retention and crash-scratch cleanup require an exclusive nonblocking lock. `.candidate-*.mp4` is private scratch: regular inactive files older than six hours can be swept without a manifest; it also participates in normal heavy-media retention. This lock is released by descriptor close or process exit, not by elapsed capture time.

This ABI is used only for Window captures with pinned owner identity and a window-only SCK source. Display/Region retain main's SCK movie and screenshot paths, never create this writer, and never enter its finish timeout. This correction does not certify legacy movie privacy through the synchronous-stop observation gap. A post-stop prompt check can discard affected screenshots but cannot prove the absence of transient prompts during native stop. Safe screenshot-only captures with no movie remain supported. See the contract document for the exact scope and remaining Mac proof.

`enqueue_sample` takes Rust's borrowed +0 `CMSampleBufferRef` from the SCK image callback. It checks for an image and retains the sample before returning; the serial worker releases the retain exactly once. The `capture_clock_ms` is the **bundle capture-clock epoch**, nonnegative and strictly increasing, not the sample's raw host-clock PTS. Rust must establish the mapping from actual SCK timestamps, `started_at` and `video_offset_ms` before calling. `enqueue_final_rgba` expects tightly packed RGBA8, top-left rows, copies all bytes before returning, and converts to BGRA in the worker. The screenshot must come from a fresh, identity-checked target (and acknowledged prompt-exclusion filter); this library cannot establish either. Source dimensions may differ from the fixed even output canvas and are stretched into that canvas; callers must not pass pixels cropped/reprojected from a different target. Both inputs feed **one** AVAssetWriter and **one** adaptor. `pts_ms` must be strictly greater than the last accepted stream timestamp. There is no duration cutoff.

The pending queue holds at most eight retained frames including the final. Return codes: 0 accepted/completed; 1 invalid input or missing final; 2 queue overloaded; 3 non-increasing timestamp or post-final enqueue; 4 encoder/finish/validation failure; 5 closed handle. Errors poison the candidate, including overload; earlier queued work may still drain but `finish` cannot return 0. A sample accepted with 0 can fail asynchronously, so **only a successful `finish` plus tail packet and decoded-pixel validation and Rust's privacy checks** permits publication. The callback only takes a short state lock and enqueues; it never waits for AVAssetWriter readiness. The worker waits at most two seconds per frame, and finish waits at most 15 seconds for AVAssetWriter completion after draining the bounded queue; a stalled encoder fails closed. `finish` is blocking and must never run on the SCK callback queue. The Rust caller must not call `finish` while callbacks are in flight. The native validator reads a bounded tail, requires increasing packet DTS ending near the stop PTS, and compares decoded end pixels to the checked stop screenshot; an inconclusive read refuses publication. It uses no ffprobe subprocess. Rust atomically replaces the original only after this validation succeeds, retaining `audio.wav` separately.

The isolated Mac VM built the Rust and Swift paths, passed its full suite, installed the app with a verified signature and produced real decoded Finder recordings through the candidate path, including GUI Window capture. The production-ABI regression for sparse-window and reader-marker behavior also passed. These tests do not prove every failure branch or callback race. The remaining native checks are in `docs/issue-99-mac-writer-contract.md`. Linux static layout and offline Rust tests alone cannot prove Swift syntax, Core Image output, encoder behavior, signature loading or callback safety on macOS.
